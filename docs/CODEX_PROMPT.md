## Step 1 — `upgrade_gate/stats.py`
Pure functions with numpy/scipy, all unit-tested:
- `majority_pass(score_rows) -> Dict[(task_id, candidate), Optional[bool]]`: majority vote over repeats, ties = fail, ignore `passed is None`.
- `pair_up(majority, baseline, candidate) -> List[(task_id, base_pass, cand_pass)]`: only tasks scored on both sides.
- `mcnemar_exact(b, c) -> float`: two-sided exact binomial p-value on discordant pairs (p=1.0 when b+c=0).
- `paired_bootstrap_ci(pairs, n_boot=10000, alpha=0.05, seed=0) -> (low, high)` for `cand_rate - base_rate`.
- `compare(pairs, slice_name) -> Comparison dict` (fields exactly as `schema.Comparison`).
- `holm(p_values) -> adjusted list`.
- `by_slice(pairs, tasks) -> List[Comparison]` for every `category=`, `lang=`, `modality=` value with n ≥ 10.
- `flip_rate(score_rows)`: share of (task, candidate) where repeats disagree. This is the noise floor.
- `sequential_test(...)`: an always-valid / sequential stopping rule so a run can stop early once regression or equivalence is clear. Use a simple, documented method, e.g. a mixture SPRT on the discordant pairs. Return `{"stop": bool, "verdict": str, "n_used": int}`. Document the method in its docstring.
- `rank_disagreements(pairs, responses, tasks) -> list`: tasks where baseline passed and candidate failed, ranked by how consistent the failure is across repeats, then by category size. Each item has task_id, category, lang, base_text, cand_text, reference.

## Step 2 — `upgrade_gate/gate.py`
`evaluate_run(run_dir, baseline, candidate, max_drop=0.02, alpha=0.05, min_n=30) -> dict` (signature fixed by contract). Writes `gate.json` (a `GateResult` dict). Decision rules (put them in the docstring and in `thresholds`):
- **no-go** if any slice (Holm-adjusted p < alpha **and** delta < 0) **or** the overall CI upper bound < −max_drop.
- **go** if no slice regresses significantly **and** the overall CI lower bound > −max_drop.
- otherwise **inconclusive**, with a reason that says how many more tasks would be needed.
- `reasons`: short human sentences, e.g. "doc-image regressed −10.2 pts (95% CI −15.1 to −5.0, p=0.001) even though overall improved +2.4 pts".
- `cost`: sum of `cost_usd` per candidate from responses, plus judge cost from scores.
- Include the noise floor (`flip_rate`) in the output under `overall["noise_floor"]`.

## Step 3 — `upgrade_gate/report.py`
`write_report(run_dir) -> list[str]`. Writes `report.md` and a single self-contained `report.html` (inline CSS, no external requests, light and dark mode, readable on mobile). Content, in this order: decision banner (GO / NO-GO / INCONCLUSIVE + one-line reason), headline numbers, a slice table sorted worst-first with CIs, a CI "forest" chart as inline SVG, cost comparison, top 10 regressions showing reference vs old vs new answers side by side, method notes (McNemar, bootstrap, Holm, majority vote, noise floor).

## Step 4 — `upgrade_gate/export.py`
`export_regressions(run_dir) -> list[str]`. Writes into `run_dir/exports/`:
- `promptfoo.yaml`: a valid promptfoo test suite. One test per confirmed regression, `vars` = prompt, assertion from the task's reference (e.g. `equals`, `contains`, `is-json` + `javascript` for fields).
- `test_regressions.py`: a pytest file with one parametrized test per regression. It calls a `call_model(prompt)` fixture the user supplies, and asserts the reference. It must import and run (skip cleanly if no fixture).
- `regressions.jsonl`: raw list.

## Step 5 — `ui/` web dashboard (this is what the demo video shows; make it look great)
Vite + React + TypeScript, no backend. It loads a run folder's `gate.json`, `tasks.jsonl`, `responses.jsonl`, `scores.jsonl`. In dev it reads `ui/public/runs/<run_id>/` and lists runs from `ui/public/runs/index.json`. Add `ui/scripts/sync-runs.mjs`, which copies `../results/*` and `../tests/fixtures/run_demo` into `public/runs/` and writes the index.

Screens:
1. **Gate verdict:** big GO / NO-GO with the reason sentence, overall delta with CI, cost delta, noise floor.
2. **Where it broke:** slice bars (delta with CI whiskers), worst first; click a slice to filter.
3. **Case viewer:** for a regression, show the prompt, any image attachment (path is relative to the repo, so copy it in the sync script), the reference, and old vs new answers side by side with a diff highlight. Show all 3 repeats.
4. **Cost:** tokens and $ per candidate.

Design: clean, dark-first, one accent colour, big numbers, works at 1280×720 for screen recording. No placeholder lorem: use the fixture data.
