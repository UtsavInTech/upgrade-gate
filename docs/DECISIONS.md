# Decisions we can point to

These are choices visible in the repository and git history. They describe this build, including its dead ends.

1. **Score known answers before asking another model.** We wrote deterministic number, label, JSON-field and instruction checks, then a blind judge cascade for cases that need one. A model judging another model introduces a second source of error. Evidence: `upgrade_gate/scorers.py`, `upgrade_gate/scoring.py`, commit `fc211db`.
2. **Repeat tasks three times, then count each task once.** We wanted to see repeat disagreement without treating repeated calls as independent evidence. Three repeats give a majority when all three are scored. This is the experiment default, not a power calculation that proves three is optimal. Evidence: `experiments/common.py`, `docs/CONTRACT.md`, `upgrade_gate/stats.py`.
3. **Ties fail and missing scores remain missing.** A tie does not demonstrate reliable success. API errors do not become wrong answers; a pair with no scored vote on either side is excluded and reported. Evidence: contract conventions and `majority_pass` in `upgrade_gate/stats.py`.
4. **Pair old and new on the same tasks.** Comparing unrelated averages could confound model changes with task difficulty. McNemar counts discordant task pairs; the bootstrap resamples whole pairs. We adjust gate-slice p-values with Holm because we look at several slices. Evidence: `upgrade_gate/stats.py`, commits `c8ee8f5` and `1f72822`.
5. **Put a spending guard before the request.** The default local lifetime cap is $90, hard-clamped to $100, with $15 reserved for the canary inside it. The client reserves worst-case cost before sending so retries and parallel workers share a limit. This was a budget protection choice, not an accuracy parameter. Evidence: `upgrade_gate/spend.py`, commit `43c913f`.
6. **A 200-token “hello” check was too small.** On the first calls, 1.1 and 1.3 spent about 190–198 tokens reasoning and returned no visible answer. We changed the check to 2,000 completion tokens with low effort. E1 used its saved 4,000-token limit. Evidence: `findings/LOG.md`, `upgrade_gate/cli.py`, commit `38b4fd8`.
7. **Drop the OpenRouter detour.** We added a provider route in `8c939a0`, then explicitly reverted it in `43c913f` and used the Meta Model API directly. The history establishes the reversal; we do not invent an outage or a price reason that the commit does not document.
8. **Keep content and requested format as two scores.** E1's old scorer reported +1.13 points for 1.3. Reading Hindi answers showed correct alternate spellings and wrapped answers being rejected. Rescoring the same responses produced a zero paired content delta. We kept `scores.before-rescore.jsonl` locally so the mistake remains inspectable. Evidence: `bf9d635`, `experiments/out/e1_upgrade.md`, `findings/LOG.md`.
9. **Do not recollect answers to fix a scoring mistake.** Reusing saved outputs holds the model responses constant and costs no new calls. The report joins rows by task, candidate and repeat rather than trusting file order. The before/after headline restricts both snapshots to common paired tasks. Evidence: `upgrade_gate/report.py`, `results/e1-upgrade/` (local, uncommitted).
10. **Separate a release gate from exploratory slices.** The gate tests marginal category, language and modality slices. The dashboard also shows their intersections, with a separate Holm family and an explicit “no clear change” state. We do not give every tiny intersection another release veto. Missing strict scores stay unavailable. Evidence: `upgrade_gate/gate.py`, `upgrade_gate/report.py`, `ui/src/Evidence.tsx`.
11. **Show real runs and label the fallback.** Saved real runs are discovered from local directories. The committed fixture plants a document regression for offline demos and is always called demo data. Presenter mode can explain a real GO without pretending E1 contains a harmful upgrade. Evidence: `tests/fixtures/make_fixture.py`, `ui/scripts/sync-runs.mjs`.
12. **Keep serving-mode estimates separate from experiments.** We can reprice saved token usage with the repository's Standard and Contributor prices. That does not establish equal answers, latency or data handling. The UI labels estimates and will read E3's observed comparison when that run lands. Evidence: `upgrade_gate/pricing.py`, `experiments/e3_contributor.py`, `upgrade_gate/report.py`.
